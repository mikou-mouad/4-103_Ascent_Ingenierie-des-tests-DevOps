Chapitre 7 · Le concept

Build once, deploy many

une seule image : embarq:1.0.<numéro du build>, construite une fois

Image Docker

construite après les tests

e2e

tests Selenium · détruit après le build

Préproduction

déploiement · smoke tests

Approbation

un humain, un bouton · 15 min max

Production

déploiement · smoke tests · rollback

Ce qui est testé part

On ne reconstruit jamais entre deux environnements : la production reçoit l'image testée en e2e et en préprod.

Un environnement, une configuration

Même image, profil Spring différent (SPRING_PROFILES_ACTIVE) : e2e, preprod, prod.

Livraison ou déploiement continu ?

L'approbation est la seule différence. Sans elle, chaque build vert part en production.

Dans le Jenkinsfile final : Image Docker, Environnement e2e, Tests end-to-end, Préproduction (deployer.sh preprod puis smoke-test.sh), Approbation (input dans un timeout de 15 minutes), Production. L'environnement e2e est neuf à chaque build ; preprod et prod gardent leurs données. Préprod : http://localhost:8081, prod : http://localhost:8082 ; la version s'affiche en bas de la page. Pendant l'approbation, le job GitLab attend, lui aussi.
