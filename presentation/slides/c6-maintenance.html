Chapitre 6 · Le concept

Des tests qui survivent aux évolutions

<!-- reserver.html : le contrat avec les tests -->
<input id="passager-nom"
       data-testid="nom" ...>

// TestId.java, utilisé par les Page Objects
static By testId(String valeur) {
    return By.cssSelector(
        "[data-testid='" + valeur + "']");
}

Un contrat

data-testid ne sert ni au style, ni au JavaScript. Une refonte le conserve.

Un seul endroit

Les sélecteurs vivent dans les Page Objects. Une page change : une classe à modifier.

Une documentation vivante

Scénarios Cucumber, noms des tests, docs/ : versionnés avec le code, vérifiés à chaque build.

data-testid est posé sur les éléments utilisés par les tests : cartes de traversée, champs, bouton valider, messages d'erreur, référence, statut, montant. Qui le maintient ? Celui qui modifie la page, comme il maintient le reste du contrat. Configuration par environnement : -Dapp.url lance les mêmes tests sur e2e ou en préproduction (attention aux données qui y restent). Documentation vivante : elle est exécutée ou générée à chaque build, elle ne peut pas mentir longtemps ; un wiki, si.
